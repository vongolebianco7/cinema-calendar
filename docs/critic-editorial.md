# 批評データの編集手順

`data/critic_evidence.json` は GitHub Pages から静的に配信する編集済みデータです。公開ページからレビューサイト、動画サイト、生成 AI、有料 API へ問い合わせません。

1. 人が公開されている批評本文・許諾された動画の内容を個別に確認し、公開元の利用条件とリンク可否を確認する。ログイン制限や転載禁止の回避、自動巡回、本文・字幕の取得・保存はしない。確認できない出典は登録しない。
2. 出典ごとに記事／動画単位の固有 `id`、批評者を含む `name`、`publisher`、HTTPS の正規 `url` を記録する。紹介記事が他人の批評を引用している場合、直接読めない原記事を確認済みとして扱わない。
3. AI に下書きの整理を手伝わせる場合も、確認済みの出典に限る。編集者が各要約と出典の対応を再確認し、推測や原文に近い表現を削除する。公開サイトは AI を呼ばず、レビュー作業に従量課金サービスを使わない。
4. `overview` は独立した批評3件以上を確認した場合だけ、2文ほどの短い独自要約を書く。`positive` は1項目につき2件以上。`divided` は意見の両側を別々の出典で確認し、`positiveSourceIds` と `negativeSourceIds` に分ける。
5. `stances` は個々の批評全文を確認して立場が明らかな場合だけ登録する。10件以上あって初めて割合を表示する。件数は今回確認した出典に限定し、世論とは呼ばない。迷う批評は `mixed` とし、判定不能なら登録しない。
6. `node scripts/check_critic_evidence.js` と `python scripts/check_critic_map.py` を実行し、作品ページを開いて出典リンクと文章を目視で確認する。

出典不足なら作品のエントリーを作らない。追加したい作品があっても根拠の不足を文章で埋めない。
