# Ocean v0.9 — asset-led visual rebuild

## Decision
Stop trying to manufacture production-grade ocean art from primitive procedural geometry. The rendering code owns motion, depth, interaction and ecosystem state; art assets own visual fidelity.

## Scope
- Replace the pre-baked-animal backdrop with a clean reef/water habitat that does not pretend to be user-generated life.
- Keep all foreground animals tied to Cinemap ecosystem records.
- Preserve local-only movie records, existing Ocean growth rules and iPhone-first gestures.
- Start at a wide establishing view; dragging explores a larger habitat and reset returns to that view.
- No bubbles / bubble clusters.
- Keep the runtime free: no paid API, AI endpoint, tracker, scraper or metered service.

## Visual source
Environment feasibility was validated against `Great Barrier Reef photos 06.jpg` by Grandmaster Huon on Wikimedia Commons, released under CC0 1.0. The image contains reef/water habitat rather than a staged collection of large hero animals. Source: https://commons.wikimedia.org/wiki/File:Great_Barrier_Reef_photos_06.jpg

For this iteration the browser may load that single CC0 static image from Wikimedia while the renderer and fish assets remain local. No automated crawling or API is introduced. A later asset-vendoring pass is preferred if repository tooling allows binary ingestion without weakening provenance.

## Rendering architecture
1. Habitat backplate: photographic reef/water, darkened and graded to Cinemap's palette.
2. Water layer: lightweight shader/CSS atmosphere for light shafts, depth haze and subtle marine snow; no bubble sprites.
3. Life layer: existing local WebGL fish mesh/texture only for organisms generated by `ocean-ecosystem.js`; reduce duplicate-looking density and emphasize scale/depth variation.
4. Camera: wide initial view; drag shifts camera and backplate at different rates; pinch adjusts field of view.
5. UI shell: keep the existing minimal header/footer and visible Ocean version.

## Quality gate
A change is not releasable merely because CI passes. Before main:
- inspect the 390×844 CI screenshot;
- reject if it looks like icons pasted on a background, if pre-baked animals dominate, or if the environment reads as a flat gradient/debug scene;
- reject if the first view feels close/cropped rather than an establishing shot;
- reject if bubbles reappear;
- deterministic smoke must still pass and WebGL fallback must not trigger.

## Compliance
The selected environment source is CC0. No copyrighted movie artwork, user data, paid infrastructure, runtime AI or scraping is added. External access is one static CC0 image request, not a data-collection integration.
