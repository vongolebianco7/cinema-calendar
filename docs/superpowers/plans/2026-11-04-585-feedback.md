# Issue 585 Implementation Plan

Goal: anonymous private feedback, authenticated triage, privacy-safe analytics on existing free infrastructure.
Architecture: static HTML uses existing Next API and additive Postgres tables. No user account system exists; administrator uses a 32+ character server-configured bearer secret, held only in page memory. Existing browser records and origin remain unchanged.
Spec: GitHub Issue #585 and the user's 2026-11-04 implementation directive.

## Constraints and decisions
- Reuse PostgreSQL/Prisma; create only new tables via reviewed SQL, never db push/reset against production.
- Fail closed when secrets, database or schema are missing. No false successful submissions.
- Server origin allowlist, bounded JSON body, plain text rendering, honeypot, durable atomic per-IP/hour and global/day caps. Store only rotating HMAC IP hashes in rate buckets, never raw IP.
- Administrator API checks constant-time token equality before any DB access; no public listing. No automatic GitHub publication.
- Web Analytics via official same-origin script, redact query/hash and exclude admin. Verify current Hobby limits before enabling optional custom events.
- Free plan and existing records/ratings/bookmarks unchanged.

## Review focus
Concurrent requests must not bypass limits; unavailable persistence must not claim success; invalid credentials must never read data; arbitrary submitted HTML remains inert text; URLs/search/email/tokens must not enter analytics.

2. Build feedback.html/admin-feedback.html plus js/cinelva-feedback.js and matching theme-aware CSS; common menu link in theme.js; privacy policy. Browser test anonymous submit, admin status flow, denied token, mobile themes and stored-record preservation.
3. Add js/cinelva-analytics.js via common theme loader; verify URL sanitization, consent/DNT behavior, search/save/bookmark allowlist with no payload. Add tests and free-plan runbook.
4. Run full shared quality gate, backend build, Chromium/WebKit CI; review complete diff. Create PR, wait exact-source four workflows, receipt-only production proof, final-head CI, merge then verify deployment. Apply additive schema only after publication proof and confirmed free quota.
